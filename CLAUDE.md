## Project Overview

`canticle` (module `github.com/sydlexius/canticle`, matching the repo after the transfer from the doxazo-net org to the sydlexius personal account; the `cmd/mxlrcgo-svc` directory, config paths, and systemd unit names retain the historical `mxlrcgo-svc` string) is a Go tool for fetching synced lyrics. It has two faces: a one-shot `fetch` CLI that writes `.lrc` / `.txt` files, and a stateful `serve` mode -- an HTTP server with a durable SQLite work queue, a background worker, a library scan scheduler (+ optional filesystem watcher), multi-provider orchestration, encrypted-at-rest secrets, and a browser-authenticated web UI. Global state is eliminated; the API token is externalized; config is TOML.

For the full per-package reference, see the "Package catalog" section below. Deeper stack and convention detail is discoverable from `go.mod`, the `Makefile` (`make help`), `.golangci.yml`, and `docs/DEVELOPER.md` -- keep the catalog current when the package surface changes.

## Architecture (one-paragraph orientation)

Cmd/internal layout. `cmd/mxlrcgo-svc/main.go` is the entry point for the released `canticle` binary and owns no business logic; it parses the subcommand tree, loads config + DB, builds the dependency graph, and dispatches. The command tree lives in `internal/commands` (`fetch`, `serve`, `scan`, `library`, `keys`, `secrets`, `config`, `queue`, `provenance`, `realign`, `revalidate`, `timing-accuracy`, `completion`). Two principal paths run under `internal/`: **fetch mode** -- `scanner` parses CLI/text-file/directory input into an in-memory `queue.InputsQueue`, `app` drains it sequentially, `musixmatch` fetches (a `Fetcher` interface), and `lyrics` writes `.lrc` / `.txt` / instrumental output (a `Writer` interface); and **serve mode** -- a `scan` scheduler over `library` roots enqueues work into the durable SQLite `queue.DBQueue`, a `worker` drains it through the multi-provider `orchestrator` (Musixmatch + petitlyrics + `innertube` `providers`, each behind a `circuit` breaker with `backoff` retry), consulting `cache`, gated by optional `verification` / `detector` sidecars (via `ffmpeg`) and `langguard`, swept in the background by the timing-revalidation pass (`revalidate` over the timing watermark, #443) and the instrumental backfill, fronted by the `server` HTTP handler (`auth` API keys, `trustnet` IP gating, optional `servetls`) and the `web` browser UI (`webauth` sessions). Shared infra: `config` (TOML, XDG paths, token precedence CLI > env > file), `db` (pure-Go SQLite `modernc.org/sqlite`, no CGO, goose migrations in `internal/db/migrations/`), `secrets` (AES-256-GCM at rest), `normalize` (NFKC cache keys), `models` (shared types, depends on nothing else internal). Dependencies are injected through interfaces -- mock at the boundary; there is no global mutable state. See the "Package catalog" below for the full `internal/`/`web/` surface.

## Package catalog

Every package with a one-line purpose. `cmd/mxlrcgo-svc/main.go` is the entry point for the released `canticle` binary (`cmd/genlib` is an internal test-data generator and `cmd/smokefixtures` builds the live serve-smoke library for `make smoke-fixtures`; neither is shipped); everything else lives under `internal/` (the directory matches the package name) except the embedded web assets under `web/`.

**Core fetch/write path**
- `models` -- shared data types (`Track`, `Song`, `Lyrics`, `Synced`, `Inputs`, `Library`, `ScanResult`, ...); depends on nothing else internal.
- `musixmatch` -- Musixmatch desktop API client + `Fetcher` interface; parses the nested JSON into `models`. An HTTP 403 on a lookup is `ErrForbidden` (a provider refusal such as a blocked egress address, #1372), and a non-200 error carries only a 120-byte body prefix.
- `petitlyrics` -- petitlyrics.com provider adapter, used as a fallback lane.
- `innertube` -- YouTube Music's unauthenticated internal ("innertube") API adapter, tokenless like petitlyrics; owns the three-call flow (search, next, browse) and the client-string selection that picks a timed-cue response over a plain-text one (`ANDROID_MUSIC`/`IOS_MUSIC`, never `WEB_REMIX`), its own pacer with a 2s policy floor (`MinAllowedInterval`, distinct from petitlyrics' 10s), and search-result verification (the search call never signals "no match", so a caller must independently confirm a candidate corresponds to the requested track). This lane MULTIPLEXES per track between upstream lyric licensors (Musixmatch or LyricFind) rather than being its own source; it reports the per-result licensor separately from the lane name so `[source:innertube]` stays constant while `[upstream:]` carries the licensor -- see `docs/provider-attribution.md` and `docs/provider-terms.md`.
- `providers` -- provider abstraction (`LyricsProvider`, `Fetcher`, `AdaptivePacer`) plus provider-generation/version invalidation that retires stale cache entries when the provider set changes. Also `WordCapable` (Musixmatch, PetitLyrics) and `WordGeneration`, the word-capable lane set plus `WordCapabilityRevision`, which expires a "no word data" verdict when either changes (#982).
- `orchestrator` -- multi-lane orchestration (`Lane`, `Orchestrator`, parallel-race + suitability scoring); composes `providers` with per-lane `circuit` breakers. A result ends the dispatch only if it is suitable AND `lyrics.DecidePromotion` would promote it as-is, judged against the query track's `TrackLength` (the audio duration the writer later judges against) (#950): a categorical (quarantined) result falls through to the remaining lanes and ranks below any other result, and, when it is the only result, is returned with a nil error once every lane answered (a transport failure, incl. a request-shape 403, counts as an answer) so the row settles as before (done + `timing_outcome=categorical`, nothing written, never cached); while a lane did NOT answer (breaker open, throttled/auth-failing, not ready) it is returned WITH `ErrTimingRefusedUntried` for the worker's bounded wait; a cached refused entry reads as a miss; a suitable MisSynced/degenerate one is HELD (first lane wins ties, outranks every non-suitable result, and skips the instrumental-only detector lane). No threshold lives here. `SetMinCommitQuality` (ordered mode only, off by default) lets only a result at or above that quality end the dispatch, and while set replaces a wordless result's `Song.WordAnswer` with the aggregate: absent only when every word-capable lane gave a genuine no-match (#982); ungated, a lane's own absent is likewise replaced by that aggregate (so an ordinary dispatch that never asked the other word lane reads unknown). A provider refusal (`ErrForbidden` on any lane, HTTP 403) trips that lane's breaker and sets `LaneState.Refused`, but stays `OutcomeTransport`, never an auth/throttle outcome (#1372). A transport-class failure is returned as `*PartialFailureError` (same class and text) only when another lyrics lane answered with a clean miss AND every transport-failing lane's breaker is open after the dispatch (today: a refusal); a fault that leaves its lane closed (5xx, bad body, dial/TLS/timeout) is returned plain and feeds the worker's global backoff as before (a lane-level bound for those is #1375). `Refused` holds through half-open until the lane's next resolve, and is not set for `innertube.ErrClientVersion` (HTTP 400).
- `circuit` -- concurrency-safe per-lane circuit breaker modeling a provider's rate-limit/throttle response.
- `backoff` -- shared retry-delay formula (1m, 2m, 4m, ..., capped at 1h) used by the worker, durable queue, and fetch loop.
- `lyrics` -- LRC/TXT/instrumental writer (`Writer`, `LRCWriter`), `Slugify`, an `.lrc` parser, provenance-tag embedding, and fsync helpers. `WriteLRC` pairs `[re:canticle]` immediately before `[ve:x.y.z]` on every synced write (#483, the LRC-standard tool+version tags). A word-timed line (`a2Words`) ends with one trailing `<mm:ss.xx>` carrying the last word's `EndMS` when that is later than its start and still differs after formatting to hundredths (#1280); `ParseTimedLRC` drops it as a wordless marker, and files written earlier lack it (no backfill). Also owns the accept-time timing guard (`DecidePromotion`, #439): `WriteLRC` consults `timing.Evaluate` before promoting a synced result, refusing the `.lrc` and keeping the words as `.txt` on `MisSynced` (an already-settled sidecar is left untouched -- that is how the writer distinguishes an upgrade from a fresh fetch, by statting the target rather than taking a caller flag) and writing nothing on `Categorical`. Unknown duration always fails open. `WriteLRC` also owns the #553 no-downgrade guard: before any mutation (target overwrite, opposite-sidecar removal, companion removal) it compares the candidate's `Rung` (`rung.go`: none < instrumental < unsynced < line < word, agreeing with `orchestrator.Quality` on the five canonical shapes only, which `TestQualityAgreesWithRung` pins; mixed shapes (instrumental flag beside subtitles or a body, word timings `HasQualifyingWords` rejects) diverge and are recorded as known divergences, not pinned) against `RungOnDisk` (the files themselves, never a provenance header; it judges exactly what the write would remove -- the exact target, every opposite-extension case variant via `staleSidecars`, and the owned `.elrc` variants via `ownedCompanions`, the same functions the mutations consume -- and the highest rung wins, so a same-extension case variant the write leaves never blocks it; a non-regular entry is kept unjudged, and a sidecar is read only through an `O_NOFOLLOW|O_NONBLOCK` handle fstat'ed regular) and returns `ErrKeptBetter` on a strictly lower candidate, unless `SetForceOverwrite` (wired from `--update` only) is set; the error is a `*KeptError` carrying the kept file's rung, and the serve worker settles a kept row by stamping `outcome_type`/`sync_tier` from that file (never the refused result), leaving `provider_lane`, `timing_outcome` and the cache untouched. The duration judged against is `Song.AudioDurationSeconds`, which callers stamp from the AUDIO FILE, never `Track.TrackLength` (the provider catalog value the lyric was already timed against). `ClassifySynced`/`ClassifyLRCFile` (#1075) classify a `.lrc`'s on-disk sync tier (word/line/unsynced) from its cues and an owned `.elrc` companion, reusing `lrcnormalize.ParseBody` and `timing.StripWordMarkers` -- no new parser.
  `ReadSyncedLRC`/`EvaluateLRCFile` are the disk-to-`models.Song` seam (#442): they read a sidecar back off disk through `lrcnormalize.ParseBody` and hand it to `timing.Evaluate`, so an existing file is re-judged by the SAME predicate that judged it at accept time. `PlainBody` flattens cues to the words a demotion persists, sharing `timing.IsDecorative` with the guard.
  `mtimebump.go` (#505, opt-in `output.bump_audio_mtime`, off by default): the writer bumps the SOURCE AUDIO file's mtime (`os.Chtimes`, zero atime = unchanged, content never opened) after it REPLACES an existing sidecar with a different lyric body (ID-tag headers stripped; a `.txt`<->`.lrc` swap always counts); never on a first write, a kept/refused write or a no-op rewrite. The caller names the audio via the transient `Song.AudioPath` (serve worker incl. upgrade trips and word rechecks, fetch-mode directory input only; realign/revalidate/backfills, instrumental backfill and recalibrate do not set it, so they never bump; a word recheck bumps only under `word_sync_mode=replace`, since under `both` only the `.elrc` changes). `bumpIfCorrected` bumps only for a sidecar in AudioPath's directory with its stem (case-insensitive), so a multi-output row cannot bump the wrong file; the prior body is read through `readRegularNoFollow` (no FIFO block, no symlink follow) and a symlinked audio file's target is what gets bumped. The path is recorded with `selfwrite` first so the watcher drops the event; a failure is a Warn, never a rollback. `audiodur`/`audiometa` re-key on the new mtime (one re-read per mtime-keyed cache: duration, metadata, scan-failure store); `scan_results` and the settled-sidecar scan short-circuit do not key on audio mtime, so nothing re-enqueues.
- `lrcnormalize` -- pure transform (`ParseBody`, `Expand`) that expands compressed multi-timestamp LRC lines (`[t1][t2]text`) into one cue per timestamp and classifies `[key:value]` ID-tag lines distinctly from cues; no I/O. The shared foundation for the LRC-text parse lanes, the write/backfill path (#470), and the upgrade scorer (#472). Wired into the `petitlyrics` parse lane, so stacked timestamps expand at parse time and every downstream write is one-cue-per-line; `lrcbackfill` drives the `.lrc` rewrite path. Not yet consumed by #472.
- `normalize` -- NFKC cache-key normalization, duration bucketing, fuzzy-match confidence, album-artist resolution.
- `langguard` -- Unicode-script classification/filtering of lyric text against a configured language allowlist.
- `scanner` -- parses CLI/text-file/directory input into the in-memory queue; skips files that consistently fail metadata read (via the injected `MetadataFailureStore`). An instrumental marker of any provenance reopens on `--upgrade` like any `.txt` (#553); a detector version bump no longer reopens one (#1106: an ordinary scan could not reopen an already-queued `done` row, so it only cost an audio read per scan; a marker with no queue row, e.g. after a rebuilt database, is now reached only by `scan --upgrade`), and re-detection of a done row under a new model comes from the `[upgrade_sweep]` (serve mode, off by default; bypasses the cache, and the detector refuses older-model telemetry) or `scan reconcile`.
- `app` -- one-shot `fetch`-mode orchestration loop over the in-memory `InputsQueue`; depends on the `Fetcher`/`Writer` interfaces.

**Persistence and stateful services**
- `db` -- pure-Go SQLite (`modernc.org/sqlite`) open/migrate (goose), WAL, foreign keys, busy-retry, and a read-only open path; migrations in `internal/db/migrations/`.
- `cache` -- lyrics cache repository (`CacheRepo`) over SQLite. An entry is the `lyrics.EncodeCachedSong` envelope: the song plus the lane and fetch time of the fetch that stored it (#1207), which `lyrics.DecodeCachedSong` restores on a hit (only a built-in provider lane; never `Upstream`; an older entry decodes laneless), so a hit stamps `provider_lane` and writes `[source:]`/`[fetched:]`. `Lookup` falls back to the bucket-0 unknown-duration sentinel row on an exact-bucket miss, so `Invalidate` (used by `purgeprovenance`) deletes every duration bucket for a key; it also takes an `Execer`, so a caller can invalidate inside its own transaction.
- `scanfail` -- `Store` recording files that consistently fail metadata read, so the scanner skips them until mtime/size changes; satisfies `scanner.MetadataFailureStore`.
- `audiodur` -- exact per-file audio duration cache (`Store`) keyed by path and validated by (mtime, size); filled opportunistically wherever a file is already open, from that read's own handle rather than a path re-stat. A miss is `unknown_duration`, never an error (#441), and `revalidate` (#442) is its consumer: a miss fails open there rather than remediating. The scanner ALSO fills it for files it skips for fetching (#684): a settled sidecar short-circuits the scan ~200 lines before the enrichment probe, so files that already had a sidecar were never duration-probed by an older build -- a coverage gap by construction rather than a lookup or invalidation failure, which is what the measurement showed for the bulk of the population (a full scan banked 690 durations and moved `unknown-duration` by zero). That is the LIKELIEST cause of a large unknown-duration count, not the only one: `revalidate.durationOf` also reads unknown when no duration store is wired and when a companion audio file cannot be stat'ed, neither of which a re-scan fixes. That fill is gated on a `Lookup`, so a skipped file costs one header read per file VERSION, not one per scan; ungated it would keep the library disks permanently awake, which is the symptom #684 exists to remove.
- `revalidate` -- re-judges `.lrc` files ALREADY on disk against their companion audio's exact duration and plans remediation (#442): demote a `MisSynced` lyric's words to `.txt`, quarantine a `Categorical` one. Owns no predicate and no filesystem machinery -- the verdict is `timing.Evaluate` via the `lyrics` disk-to-Song seam, the duration is `audiodur`'s, and every mutation goes through `realign.Apply`. `Plan` and `Apply` are separate calls, so the CLI's dry-run default provably writes nothing; unknown duration never remediates; removal is a MOVE (quarantine) unless `--purge`. Two entry points share one core: `Plan` WALKS library roots (the CLI), and `PlanCandidates` judges an explicit list of `work_queue` rows without reading a single directory (the serve-mode sweep, #443) -- a row records its audio path, so the sidecar is DERIVED (`stem + .lrc`) rather than discovered, and a cycle costs its batch, never the size of the library. An extension-case variant (`track.LRC`, #989/#1051) is resolved by up to 7 extra `Lstat` calls (2^n permutations of an n-letter extension, minus the exact case already tried) against the extension's own case permutations when the exact-case name misses -- never a directory read, so the batch-cost property holds for that population too -- and a demotion's `.txt` target is resolved the same way, ordered to match the scanner's own resolver (`Listing.Variants`, name order) so the two agree on which real file to land on, instead of creating a second, differently-cased one. In candidate mode EVERY candidate returns a finding, including the un-judgeable ones (`no_sidecar`/`no_audio`/unknown duration), because the caller stamps what it gets a finding for and an unstamped row head-of-lines the oldest-first batch forever. Its two failures are separated by BLAST RADIUS: an unparsable `.lrc` concerns one file, so it is counted and the row is left UNSTAMPED (an unreadable file is equally what a transient I/O error or an unavailable mount looks like, and the stamp is one-way, so it is retried rather than retired); a duration-store failure concerns the whole batch, so it abandons the cycle rather than stamping rows it never judged.
- `queue` -- the in-memory `InputsQueue` (fetch mode) and the durable SQLite `DBQueue` (serve/worker mode) with priority tiers and randomized within-tier dequeue. An `Enqueue` collision keeps a settled or in-flight row's paths, except that a row whose source file is gone is moved to the incoming same-directory, same-stem file that replaced it (`enqueue_move.go`, #1262: a format swap), telemetry kept; never a `processing` row, never while the old file still exists or its stat fails for any reason but not-exist, and a row prune retired as unresolvable is reopened as prune's own relink does. A second exception (#972): a scan enqueue carrying `Inputs.ReopenCategorical` (set by `scan.Enqueuer` when the file's known duration differs by more than `timing.Tolerance` from the duration the row's categorical verdict was judged against, derived by `LookupTiming` from the stored overrun, a read that ignores the row's status) is judged again inside the enqueue transaction: a `done` + categorical row is reopened and moved to the incoming file, while a categorical row that would keep its paths (`processing`, `unavailable`, in an upgrade trip, a `done` row prune retired over a queued word recheck, or junction-linked to another file's `scan_results` row that is not `done`) fails the enqueue with `ErrCategoricalNotReopened`, nothing written or linked, and the scan leaves the file pending for the next scan (counted and logged as refused, separately from the suppressed count); a row no longer categorical, or pending/failed/deferred outside an upgrade trip, enqueues as usual (a parked word recheck, `deferred` + queued, is reopened by the scan before this check, as on any scan collision). A row that records a file or a hand edit (`categoricalFileless` false: `outcome_type` or `sync_tier` set, or `lyric_edited_at` set; a sweep stamp under `on_categorical = off` and a hand-edited row both keep their `.lrc`) is never reopened: `LookupTiming` reports no judged duration for it, so the scan does not ask and suppresses it as before, and the in-transaction check refuses it too. Known limit of the link guard: while the judged recording's own `scan_results` row is pending or processing and still linked, the other recording is refused on every scan until that row settles. The state arises after a forced `--update`/`--upgrade` scan and persists after a later provider-generation change; main does not fetch it in that state either, and per-recording verdict state is tracked in #1366. Unknown duration or an underivable verdict keeps the suppression. `RepointGoneSource` is the same move with no enqueue (retrying on `SQLITE_BUSY`), and also relinks a row already at the incoming path whose `scan_results` link is missing or still names the vanished file: a path-only move (a webhook before any scan) keeps that old `scan_results` row until then. The move is library-scoped (`Inputs.LibraryID`, which `scan.scanInputs` carries): it links and settles the scanning library's `scan_results` row and removes only that library's row for the vanished file, and an overlapping library's own pair is repaired when that library scans the replacement (`planLibraryRelink`, `scan_result_id` untouched). Completion stamps (`SetOutcomeType`, `SetCompletionProvenance`, `SetTimingOutcome`, `SetSyncTier` #1075) are written before `Complete` while the row is still `processing`; each is non-fatal, since the output is already on disk by then. `sync_tier` (word/line/unsynced) is deliberately separate from `word_timing_state`: it records what the FILE is, not whether a provider lane answered. `upgrade_sweep.go` (#553): `ListUpgradeCandidates`/`MarkUpgradeQueued` re-queue settled rows below line sync (not the timing-remediation guard, not word-recheck rows, not settled or admitted within a week) as `pending`, stamping `upgrade_checked_at` and arming `upgrade_queued` (an upgrade trip). An armed row is protected like a word-recheck row: an Enqueue collision keeps it armed with its `completed_at`, and `notWordRecheckQueued` keeps it out of Cleanup, library cancel and every miss sweep; a migration-053 trigger disarms it on ANY move to done/unavailable. `SetRemediatedFileState` (#1130) re-describes a row after a timing remediation (outcome `unsynced` or NULL, `sync_tier` cleared, `processing` rows left alone). `work_queue.upstream` (#1297, migration 065) records the licensor of a multiplexing lane's result; it is written by `SetProviderLane` in the SAME statement as `provider_lane` (so the pair always describes one result, a rejected one included), reduced by `lyrics.RecordedUpstream` (the writer's `[upstream:]` rule). It follows `provider_lane`, NOT the file: it equals the `[upstream:]` tag wherever a tag block is written (a tagged `.lrc`, a provider instrumental marker) and is still recorded where the file has none (an unsynced or demoted `.txt`) or nothing is written (a categorical result). It is cleared by every path that clears or replaces `provider_lane` (`ClearProviderLane`, `SettleInstrumental`, `UnsettleInstrumental`, `ReopenDoneRowTx`); paths that keep the lane keep it. `SettleUpgradeTrip` settles a trip that landed nothing back to done with the file record untouched. The first arm escalates its hold (#1118, migration 064 `upgrade_miss_count`): an admitted row waits the base week times 2^MIN(misses, `UpgradeMaxHoldDoublings`=3) (1, 2, 4, 8 weeks), the base cut being the caller's `holdBefore`; an ANSWERED `SettleUpgradeTrip` counts a miss, an unanswered one does not, and `Complete` of an armed trip resets it (a landed or kept result). The mis_synced arm is not escalated (its one-pass marker already bounds it). A second candidate arm (#1120, migration 055) covers post-settle `mis_synced` rows: `TimingRecord.Source` (`work_queue.timing_stamp_source`) is `fetch` for the worker's stamp (every lane already answered; never re-asked), `sweep` for `runTimingValidationSweep`, `revalidate` for `SetTimingOutcomeIfIdle` (its only caller), NULL for a pre-055 stamp (read as post-settle); such a row gets ONE trip under the providers generation, recorded in `missync_recheck_generation` only on an answer: `SettleUpgradeTrip(answered=true)`, or `Complete` for a trip whose result the no-downgrade writer kept out (a lane answered; a transport-cap or verifier-error settle leaves it unrecorded and the row re-offered after the week hold; a landed trip re-stamps the row at fetch and leaves the arm); a lane-set change re-opens it, any post-settle stamp clears it. An empty `Source` stores NULL (read as post-settle, never skipping a pass); an unknown one is an error. The worker writes such a trip only for a result judged exactly `ok` against the audio file's own duration (`resolvedTrack.TrackLength > 0`), else settles it.
- `library` -- library-root CRUD repository (`Add`/`List`/`Get`/`GetByName`/`Update`/`Remove`).
- `scan` -- library scanning: `Enqueuer`, the `scan_results` `Repo`, and the periodic scheduler that enqueues missing lyrics. `Enqueuer.RepointSettled` (#1262) hands the settled files a scan just indexed to `queue.RepointGoneSource`, since a replaced file whose sidecar survived is never pending and so never enqueued. One-shot: only the scan that first indexes the replacement offers it, so a copy-scan-then-delete re-rip, or a stat/database failure on that scan, leaves the row on the vanished file until prune's same-stem sibling relink (a later #1262 slice).
- `worker` -- durable-queue `Worker` that drains work items through the providers/orchestrator and cache. On `ErrTimingRefusedUntried` (#950) it parks ONLY that row via `queue.DeferRefused` (its own `refused_waits` counter; attempts/miss_count untouched; wait = the breaker cap) and keeps draining, RESETTING `consecutiveFailures` to 0; the detector's miss telemetry is stamped before the park. An instrumental-only (detector) lane never counts as untried. After `maxRefusedWaits` (3) it settles the carried refused song as done + categorical, logged at Warn with the untried lane; the wait is bounded but does not guarantee the lane is ever probed (another row can re-trip its breaker), so retrying such rows is a #950 follow-up. `stampLane` writes the result's lane and its `lyrics.RecordedUpstream` into `work_queue.upstream` in one `SetProviderLane` statement on every completion, word-recheck write and verify/guard rejection exit (NULL for a cache hit, a detector settle or a lane with no upstream; it follows the lane, not the file, so an unsynced `.txt` or a categorical result still records it); a kept write stamps neither it nor the lane. A row with `word_timing_state='queued'` takes the word-recheck path (`runWordRecheck`, #982) instead, UNLESS `output.word_sync_mode` is `off` (#1054), in which case it is released back to `done` with no verdict via `queue.DeferWordRecheck`'s own wait-budget-exhausted un-flip (no lane contacted, no cache/store/write) -- closing the gap where a row queued before an operator's restart-with-off would otherwise keep draining; on any other mode it dispatches word-capable lanes only, never the cache (an entry records the fetch that stored it, not a fresh word-lane answer, and a pre-#1207 entry carries no lane or fetch time, so it could strip `[source:]`/`[fetched:]`), and it writes ONLY a result whose words pass the writer's own `lyrics.HasQualifyingWords` and that promotes as-is, so a recheck can never downgrade a settled `.lrc` or its `.elrc`; a verdict settles via `queue.SettleWordRecheck` (`served`/`absent`; absent when every word lane answered without usable words, or on a script-guard/verifier reject), an unanswered lane re-parks via `queue.DeferWordRecheck` (a healthy no-word answer does not feed the failure backoff; a transport cause, a verifier error included, does) and, after 3 waits (`refused_waits`), un-flips the row to done with no verdict; no recheck path touches `miss_count`, `attempts`, `lane_attempts`, or `provider_outcomes`, and `provider_lane` moves only after the write. An ORDINARY completion stamps the verdict too (`stampWordTiming`, non-fatal, before `Complete`): `served` only when the words landed (`LRCWriter.WordsLanded`: `HasQualifyingWords` plus inline mode or an owned `.elrc` on disk), `absent` only on the aggregate, and only for a synced outcome from a word-capable lane with `word_sync_mode` not off; anything else stamps nothing and clears a prior served/absent, as do the detector-instrumental and guard-reject settles (`clearWordTiming`, before they settle). Alongside it, `stampSyncTier`/`clearSyncTier` (#1075) record `queue.SetSyncTier` from `WordsLanded` directly -- independent of `ordinaryWordVerdict`, so a line-synced completion under `word_sync_mode=off` or from a non-word-capable lane still tiers correctly; a word-recheck write (`writeWordRecheck`) stamps `word` only when the words actually land at every output path (`WordsLanded`), else `line` (`wordRecheckWritable`'s gate is necessary but not sufficient -- a foreign `.elrc` can still block landing, #1075 finding 1); either stamp's failure clears the tier to unknown instead of leaving the row's prior tier stale (`stampOrClearSyncTier`, #1085 review), and if the clear also fails the row is not settled but retried (CodeRabbit thread 4098910896). On an `orchestrator.PartialFailureError` (#1372: a lane this dispatch opened, another lyrics lane answered) the row still takes `queue.Fail` (its own retry, no miss charged) but `consecutiveFailures` is reset, not bumped, and the word-recheck path (`classifyWordRecheckFailure`) resets it the same way; any other transport failure feeds the global backoff as before. Known limit: rows the answering lanes miss while a lane is open are charged an ordinary miss (#1374).

Chips carry no counts (tier/edited are unindexed, and the Settled mis-synced count is not a covering-index read once composed with the Settled bucket clause). `BucketFilter.Reason` (`bucket.go`, #1235) is the Retrying/Errored failure-reason filter: one ordered CASE over the RAW `last_error` (case-insensitive substring markers, plus `GLOB` for the 5xx statuses; `failsig.Classify` cannot run in SQL), so the categories (none/write/throttle/network/miss/other) partition by construction, `other` being the ELSE; `ReasonCategories` is the one place a bucket's offered set is decided (Given up is not offered: every row there reads `miss limit reached`), and `web` parses `reason` through `HasReason`. A scan of one status's rows, not indexable; cost scales with message bytes (about 125 ms at 14,000 rows of short messages, about 3 s at ~4 KiB messages under title sort). The web layer is the caller: `queueViewState` parses `tier`/`edited`/`missync` (unknown values and chips the bucket does not offer are ignored; a URL carrying both the line tier and `missync` keeps `missync`, so the filter never sets both) and every sort/pager/search/back link carries them. `BucketFilter.LibraryID` (#1235, every bucket) is an `EXISTS` over `work_queue_scan_results` with `+scan_result_id IN (SELECT id FROM scan_results WHERE library_id = ?)` (never a JOIN, so a row linked to several files or libraries cannot repeat and break the keyset cursor; a row with no scan link never matches). The unary plus is load-bearing: without it SQLite probes the junction primary key with both columns and walks the library's whole IN list per candidate row (quadratic; seconds, then the write timeout, at ten thousand files, since production never runs ANALYZE), so `TestLibraryPredicateUsesPrefixProbe` pins the `work_queue_id=?` prefix-only plan; `Repo.Libraries` feeds the Library `<select>` in the search form, and the handler drops a `library` id naming no library (a repeated `library` is a 400). `BucketFilter.Lane` (every bucket) is `provider_lane = ?` for a value in `reports.Lanes()` (the `providers` names, labeled by `reports.LaneLabel`; the detector lane and a NULL lane are not selectable, so "Source" cannot isolate detector-settled or cache-hit rows), surfaced as the "Source" select; a row keeps its lane through a retire, an upgrade trip and a verify failure, so non-done buckets carry it too; any other value is ignored and a repeated `lane` is a 400. The report also links to `/queue/settled?missync=1`, which shows the settled mis-synced rows, a subset of the report (categorical and unsettled rows are not in it).
- `secrets` -- encrypted-at-rest (AES-256-GCM) store for recoverable runtime secrets, persisted as opaque BLOBs.
- `watcher` -- optional filesystem watcher that triggers targeted library scans on change; complements, never replaces, the periodic scheduler. Consults `selfwrite` in `translate` to drop the events canticle's own sidecar writes generate, before they can prune or arm a debounce timer (#685).
- `selfwrite` -- a TTL'd, concurrency-safe set of paths this process just wrote, shared in memory between the `lyrics` writer (which records) and the `watcher` (which suppresses). A leaf package, so neither side depends on the other. Suppression keys on the FILE path, never its directory, so an external change to a sibling in the same album folder still triggers a rescan; a recorded final path also covers its `os.CreateTemp` temp file by derivation, closing the race where the temp file's Create event outruns the writer's knowledge of the random name. Entries expire (serve wires the TTL to a small multiple of `watcher.debounce_ms`), so a crash or an undelivered event can never leave a path permanently deaf to external change. A nil `*Registry` is a safe no-op for every non-serve caller.
- `prune` -- reconciles `work_queue`/`scan_results` against the filesystem: rows whose source audio file has vanished are deleted (`os.Stat` is the sole authority; `Directory` granularity for the periodic sweep, `Exact` for the reactive prune and `scan reconcile-paths`; an in-flight guard defers rows whose linked work is still `processing`). A gone row is relinked instead when a unique MBID/ISRC match, else (#1262) exactly one present same-stem sibling with another extension (an in-place format swap; found by an index range over `scan_results`, one stat per indexed sibling, never a directory read; outdir, filename and `output_paths` kept, every overlapping library's row for the sibling linked, or only the requested library's in a library-scoped sweep; retained instead on two siblings, a sibling junction-linked to or already the `source_path` of a different queue row, a sibling whose MBID/ISRC differs from the row's own (a differing title is not a contradiction), or a sibling whose stat fails with anything but not-exist; a gone path with only a `scan_results` row and no queue row is not this tier's and stays as before), else an exact-title name match resolves it. It covers what `queue.RepointGoneSource` misses. The periodic `Directory` sweep sees an in-folder swap through `dirstate.go` (#1262, migration 060 `prune_dir_state`): a recorded directory costs one stat, and its row files are stat'ed exactly only when it is unrecorded, its mtime differs from the stored one, or it was recorded with a row still gone and `MAX(scan_results.id)` has advanced since (a scan indexed something, which is how a replacement already on disk becomes relinkable). A directory with a gone row is recorded too (with that mark), so it converges; one whose mtime is under a minute old or in the future, or that holds an unreadable or `processing` row or a relink a worker raced, is not, and is examined next sweep. A dry run or library-scoped sweep stores nothing, a failed store is logged and never fails the sweep, and state under no configured root is dropped (kept under a configured root that is unavailable). The detector assumes the directory mtime seen through the library path moves on an in-folder change: verified 2026-10-03 on the Unraid user share (a folder on one branch, on two branches, and after a branch's copy is removed): the directory mtime seen through the share moves on every in-folder add or delete, reporting the newest branch's value, and can move backward when a branch's copy is removed, which the "differs" comparison handles. A row classified for deletion that is also junction-linked to a PRESENT file in another library is retained, never deleted (#1293; one junction lookup, then a stat per such link, only on rows already headed for deletion; a link under no available library root counts as present, since an unmounted share reads empty; the delete would cascade away the other library's link; a source with no `scan_results` row of its own counts every link to another file, and the delete transaction re-checks, so a scan linking one after the preflight keeps the row whole). A sibling relink declined because another queue row owns the sibling is recorded too, so it is retried only on a directory change, a scan insert, or `scan reconcile-paths`. A row gone inside a surviving directory runs under `policyInFolder` there: relinked to its same-stem sibling or retained, never retired, and never relinked by MBID/ISRC or title (no identity pool; `scan reconcile-paths` does that); a removed directory is unchanged. Such a row is deleted only by AGE-OUT (#1262, migration 061 `prune_gone_since`: path, `first_seen`, `confirmed_at`): the unscoped periodic sweep marks it when it can neither relink it nor tie it to a present file (a row held for an ambiguous, owned, contradicting or unreadable same-name sibling, for an indexed file carrying its MBID/ISRC that is present, unreadable or under no available root, which is one indexed query and a stat per match, or for the one present file the name tier would relink it to by title under that tier's own gates, which reuses `tryNameRelink` at the cost of one unstat'ed read of the library's `scan_results` per sweep and a stat of the winner, never marks and never ages; a plainly completed row, or a title several files share, is not held), and drops the mark when the file is seen again, the row is relinked or held, or no row names the path. Once the mark is `goneGrace` old (one week of wall clock, a constant) the sweep examines that one file in its otherwise unchanged directory, at a cost of two stats, one directory read per directory per sweep, and one stat per indexed same-stem or same-identity candidate: a re-stat that is not a clean not-exist, an empty directory (an unmounted nested mountpoint), a directory read that fails (with entries or without), or a same-stem entry on disk that is not a `.lrc`/`.elrc`/`.txt` (a replacement no scan has indexed) refuses, and a refused mark is DROPPED, so the row is not looked at again until its directory changes or a scan inserts. Otherwise the first such sweep only records `confirmed_at`; a sweep at least `goneConfirmGap` (one hour) later, finding the same, deletes the rows through `deletePruned` (same in-flight guard and report hook; sidecars untouched). An aged-out row is BACKUP-FIRST: its report runs before the delete transaction and a row whose report failed is not deleted; if the delete then leaves any of its rows, a second report (`PrunedRow.Corrects`, a `pruned-corrected` record that replaces the first) lists what was deleted. Failed aged-out reports return one error with a count and the first cause (the CLI's names the source), except that a hook answering `prune.ErrNotRecorded` keeps the row without failing the sweep. The aged-out record also carries each queue row's `status`, `outcome_type`, `sync_tier`, `timing_outcome` and `lyric_edited_at` (`work_states`). `first_seen` is never rewritten (one later than now is not due), and no mark is started while the directory's mtime is under a minute old or in the future (so a sweep under a clock that is behind starts none); a `confirmed_at` later than now, or on a mark found not due, is cleared. More than `ageOutMaxPerSweep` (50) rows due at once is a hard stop for the unattended sweep: none is deleted and each mark is held (`confirmed_at` -1, `Result.AgeOutHeld`, one Warn with the count per sweep while any is held). No periodic sweep deletes or releases a held mark, however few remain: in an unchanged directory it is counted without a stat or a directory read, in a changed one it is dropped if the file is back or the row is relinked or held, else kept; held marks count toward the cap, so rows newly due are deleted only while held plus due stays at or under it, and are held too otherwise. Nor does any sweep age out a row whose queue row another library's different file also links (`sharedAcrossLibraries`). The exit is attended: `scan reconcile-paths --yes` (an `Exact` sweep) also deletes every row whose mark is due and confirmed or held, with no cap, under the same holds and directory check, backup first (its dry run plans the same count), then, unless it is library-scoped (a `--library` run deletes its library's due rows and releases none), releases the marks still held, so the next sweep looks at them again (a file that came back in an unchanged directory is only noticed then). `scan reconcile-paths` writes no mark; an unscoped run prints the aging and due counts and, on their own line with the `--yes` advice, the held ones (`AgingCounts`). A dry run makes the apply's ownership check (`planRelinks`), so both report the same relinks; `Result.RelinkOwned`/`RelinkChanged` count the planned relinks that did not happen, and `scan reconcile-paths` prints them. Both deletes also name the path the row was read at, so a row a scan's `Enqueue`/`queue.RepointGoneSource` moved to its replacement mid-sweep is skipped: `Result.PruneSkipped` counts such sources (0 in a dry run; `scan reconcile-paths` leaves them out of its pruned count and the serve sweeper logs the count), and a backup record lists only the ids deleted. The serve sweeper appends each source it deletes to `reconcile-paths-serve-backup.jsonl` beside the database (the CLI's record, 0600, created on the first delete); a file that cannot be opened or appended to never stops the sweep, discards its result or skips its directory-state save, and costs one Warn per sweep (the CLI instead returns a count-and-first-cause error after reporting the rest). An aged-out source is the exception to that last rule: the sweeper's `sweepBackup.report` answers `prune.ErrNotRecorded` for one whose record it cannot write, so the row and its mark are kept and tried again next sweep, and that sweep's one Warn carries the kept count (`aged_out_kept`) beside the unrecorded one (which also counts a correction that could not be written), still with no library path.
- `purgeprovenance` -- bulk-deletes `.lrc`/`.txt` sidecars matching a provenance filter (`--source <name>` or `--no-source`) and resets the coupled `work_queue`/`scan_results` rows so the next scan re-fetches (issue #474). **Sidecars, config, cross-cutting**
- `verification` -- optional acoustic verification of fetched lyrics (`Verifier`, `HTTPVerifier`) against an external service, using a short audio sample.
- `detector` -- optional audio-based instrumental detection sidecar (external AudioSet/YAMNet classifier, vendored at `deploy/yamnet-detector/`); a three-gated decision (music / sung-vocal / speech gates) sampling short windows across the track in one inference call; a legacy mean-only sidecar degrades safely to never-instrumental.
- `ffmpeg` -- resolves an ffmpeg executable for the sidecars, auto-provisioning a checksum-pinned static build when none is configured or on PATH.
- `timing` -- the shared pure predicate classifying synced-lyric timing against audio duration; sole owner of `TimingOutcome`/`Evaluate`, the exported `IsDecorative` line classifier, and the calibrated `Tolerance`/`CategoricalRatio` constants (#438). Consumed by all four callers now: the accept-time guard in `lyrics`, the worker's outcome stamp, the `revalidate` backlog pass (#442), and the serve-mode sweep (#443). **The thresholds are NOT configurable and that omission is the design**: `Tolerance` and `CategoricalRatio` are a co-calibrated pair (tolerance is checked FIRST, so on short audio a large ratio still reads `Ok`), and one predicate serving all four callers is what keeps a `timing_outcome` comparable across a deployment's own history. #443's original AC listed a `categorical_ratio` config key; it was deliberately not built. A threshold worth tuning belongs here, where every caller moves together. No I/O; the max timestamp is taken over text-bearing lines only, decorative lines filtered wherever they appear, so a decorative marker past the audio end is not an overrun.
- `config` -- TOML config resolution (XDG paths, registry-driven keys, token precedence CLI > env > file) plus redaction, validation, render/write. Owns the `[timing_validation]` surface (#443), which is now LIVE: its consumer is `commands.runTimingValidationSweep`. `enabled` / `revalidate_existing` gate the serve-mode sweep (BOTH required, mirroring the realign gate), `revalidate_batch` budgets one cycle, and `on_mis_synced` / `on_categorical` select the remediation. The two action enums differ by exactly one value and the difference is load-bearing -- a categorical lyric is another song's words, so `demote` is illegal there; both sets derive from one pair of functions that `enumValues`, the settings dropdown, and the file/env re-default checks all read, so they cannot drift. An unrecognized action ALWAYS resets to the conservative default rather than falling through, so a typo can never resolve to something more destructive than what was written. Also owns `[word_sync_recheck]` (#1048, `enabled`/`batch`, dark by default, batch range 1-1000 shared by file/env/`config set`), consumed by the serve-mode word-recheck sweep (see `commands`), and `[upgrade_sweep]` (#553, same shape and range), consumed by `commands.runUpgradeSweepLoop`. `[word_sync_generate]` (#1006) drives no background sweep: the #1007 generate sweep was removed from serve (#1008 replaces it with an on-demand action).
- `logging` -- `slog` logger setup and secret redaction.
- `realign` -- confidence resolver (`Realigner`, `Move`, `Apply`) that re-attaches orphaned `.lrc`/`.txt` sidecars to renamed or moved audio: exact ISRC/MBID provenance, filesystem heuristic with a title-only Jaro-Winkler name guard plus a `min_margin` runner-up rule against the directory's other audio (#672: the artist is excluded and both name tiers must agree on a pair, or a shared artist name renames a sidecar onto the wrong song), an opt-in N:M name-similarity matcher (`heuristic-nm`, config `name_match`/`min_margin`) for a directory with multiple orphans and multiple sidecar-less audio files, ambiguous, conflict. Backup-first and clobber-safe; shared by the `realign` CLI command and serve-mode reactive realign (watcher / scan / Lidarr-webhook). `Apply` also carries the REMEDIATION action kinds (`KindDemote`/`KindQuarantine`/`KindPurge`, #442) so `revalidate` reuses this one apply path and one JSONL backup trail rather than standing up a second remediation stack; `KindRename` is the zero value, so every pre-existing `Move` is unchanged.
- `commands` -- the CLI command tree: top-level `Args` and every subcommand (`fetch`, `serve`, `scan`, `library`, `keys`, `secrets`, `config`, `queue`, `provenance`, `realign`, `revalidate`, `timing-accuracy`, `completion`). The `timing-accuracy` subcommand (#1117) calls each lane's `FindLyrics` directly against a local hand-verified reference set and prints aggregate-only line-start error per lane and per upstream; it opens no database and writes nothing. The `revalidate` subcommand is thin CLI wiring over the `revalidate` package, dry-run by default behind `--apply` (not `--yes`) and AGGREGATE-ONLY on stdout -- no path, artist, title, or lyric text is ever printed, since a sidecar path carries the library's private metadata; `--tail` is the one place per-file detail lands. Under `--apply` it then stamps each remediated file's coupled `work_queue` row (#1082) through the sweep's own `timingRecordFor` + `SetTimingOutcome`, resolving file to row via `queue.IDsBySourcePaths` over every same-stem audio sibling (`revalidate.SiblingAudioPaths`; the one row may name either copy) and skipping any action that failed (or any audio file with a failed sidecar), so the remediation guard (`timing_outcome` NOT IN categorical/mis_synced/degenerate, shared by the reports' sync-tier arms and the word-recheck predicate; the review queue is deliberately narrower) excludes it. Both then call `restampFileState` (#1130) so the row's outcome/tier match the file left on disk. `runTimingValidationSweep` (#443) is its serve-mode counterpart: the same core, driven from the `queue.ListTimingBacklog` watermark instead of a walk, gated on `timing_validation.enabled` AND `.revalidate_existing`, applying BEFORE it stamps so a failed remediation leaves its row in the backlog to retry. A stamp write that fails AFTER the remediation applied is retried in-process only on SQLITE_BUSY (`retryStamp` over `db.RetryOnBusy`, 4 tries; any other error fails at once; #1136) by both the sweep and `revalidate --apply`, since the sidecar is gone and no later pass can rediscover it; one that outlasts the retries is still only logged (sweep) or counted and exits non-zero (CLI). The `realign` subcommand is thin CLI wiring over the `realign` package (above); `scan reconcile-paths` drives `prune` on demand, `scan reconcile-identity` drives `identityrepair` on demand, `scan reconcile-word-sync` flips settled synced rows to `word_timing_state='queued'` via `queue.MarkWordRecheckQueued` for the serve worker's recheck path (#982; refused under `word_sync_mode=off`, fetches nothing itself); and `scan reconcile-editor-tag` (#483) backfills `[re:canticle]` onto existing canticle-written `.lrc`/`.elrc` sidecars via `lyrics.InjectEditorTag`, AGGREGATE-ONLY on stdout like `revalidate`, with a marker-gated (`editor_tag_backfill_483`) one-shot serve-startup counterpart shaped like the identity backfill (unattended, since the mutation is a single additive header line, not a body rewrite), bounded by its own `editor_tag_backfill_483_degraded_attempts` counter under the #1084-generalized `incrementDegradedAttempts`/`clearDegradedAttempts` so a permanently degraded root cannot re-walk the library on every boot forever. All are dry-run by default and write a JSONL backup of what they applied, following `scan reconcile`; the confirmation flag is `--yes` for the reconcile family and `--apply` for `revalidate`. The serve-mode counterpart of `scan reconcile-word-sync` is the word-recheck sweep (`word_recheck_sweep.go`, #1048): gated on `word_sync_recheck.enabled`, refused once at startup under `word_sync_mode=off`, on the timing sweep's cadence; each cycle admits `batch` minus the rows already `queued` through the CLI's predicate and flip, using the worker's live-lane `WordGeneration`. Its flip stamps `word_timing_checked_at` (`StampChecked`) and its candidate query holds an unverdicted row checked within a week (`UnexaminedCheckedBefore`), so a wait-budget un-flip or a scan reopen is not re-admitted every cycle (PROBE-K). The upgrade sweep (`upgrade_sweep.go`, #553) is the serve-mode counterpart of `--upgrade` (Enqueue keeps a done row done): gated on `upgrade_sweep.enabled`, same cadence, each cycle admits `batch` minus its in-flight rows, and also the post-settle mis_synced pass (#1120: the sweep's stamp is `queue.TimingSourceSweep`; serve's `newServeUpgradeSweep` wires the providers generation onto this sweep's queue). The worker runs an upgrade trip (`WorkItem.UpgradeQueued`) past the cache, writes it through `LRCWriter.WriteLRCNoDowngrade` (never forced, even under `serve --update`), and settles it via `queue.SettleUpgradeTrip` whenever nothing lands: a miss, a result the timing guard would not promote as-is, a script-guard or verifier reject, or the third failed attempt (`upgradeMaxAttempts`). `scan reconcile-sync-tier` (#1075) is the one-time backfill for `work_queue.sync_tier`: classifies every completed synced row's sidecar via `lyrics.ClassifyLRCFile` (deriving the path from `source_path`, with `revalidate.ResolveSidecarCaseVariant` on a case-mismatch), leaving an unreadable or missing sidecar's row NULL and counted rather than guessed; no serve-mode sweep, since a fresh completion stamps its own tier. `scan reconcile-remediated` (#1143) re-describes tier-unknown synced rows from disk via `queue.ListRemediatedCandidates`/`ApplyRemediated` (no sidecar: reset plus cache invalidation; `.txt` only: unsynced; `.lrc`: record word/line tier, with a kept remediation verdict, retired, in-flight and unsynced-`.lrc` rows counted separately), dry-run by default, aggregate-only, write-ahead JSONL backup, no busy retry.
- `timingacc` -- pure line-start accuracy measurement for `timing-accuracy` (#1117): a monotone LCS `matchLines` over `normalize.NormalizeKey` text (ties broken by smaller total start error) and `LineStats` (MAE, share within the 300 ms `WithinMS`, declared reference residual); no I/O, so it imports neither `lyrics` nor `models`. Cues pair only on equal normalized text (an empty one never pairs), and with repeated lines and a count mismatch the error is a lower bound. No MAE is reported for zero matches.
- `version` -- build-time `Version`/`Commit`/`Date` (GoReleaser ldflags) and `VersionString()`.
- `testutil` -- generates synthetic ID3-tagged audio for load/concurrency tests and the genlib tool.

Worth flagging: directory mode overrides `--outdir` (writes the output next to the audio file; the extension depends on lyric type - `.lrc` when synced lyrics are found, `.txt` when only unsynced lyrics or an instrumental marker is written), and `--upgrade` re-fetches songs that previously got `.txt` (unsynced lyrics or an instrumental marker, any provenance) to promote them when better lyrics become available, at a lookup per `.txt` per run (a provider request or more on a cache miss).

## Quality gating and CI

- Local gate: `make gate` (`scripts/pre-push-gate.sh`) runs the FULL chain behind a per-worktree run-lock: conflict markers, commit signatures (main requires signed commits), product name, gofmt, generate + build, non-race tests of the changed packages, patch coverage (skipped if the estimator is absent), golangci-lint, actionlint, PR-trigger scope guard (`scripts/check-pr-trigger-scope.sh`; no `branches:` filter on any PR workflow, so stacked PRs run CI), shard-split verify, govulncheck. The race suite is CI-authoritative; `RUN_RACE=1 make gate` opts in to the full `go test -race ./...` plus the local coverage floor and codecov dry-run (both need its whole-module profile; skipped otherwise, CI Coverage Floor / Upload Coverage own them). `.gates.toml` delegates `/prep-pr` to it, and gate-runner writes a `gate-receipt/v1` to `<git-dir>/prep-pr-receipt.json`.
- Git hooks: `make hooks` sets `core.hooksPath=.githooks` (a relative, shared git setting), so every worktree -- including new ones -- inherits the hooks with no per-worktree setup. `.githooks/pre-commit` runs conflict markers, typos, product name, gofmt, build, golangci-lint, govulncheck on staged content. `.githooks/pre-push` first runs `scripts/check-commit-signatures.sh --refs` on the pushed refs, BEFORE the receipt fast path and the `PUSH_GATE=full` override (the receipt is tree-keyed, and a `git commit-tree` re-creation keeps the tree), then does NOT re-run the full gate: it exits at once when a passing receipt's `tree_sha` matches every pushed ref on a clean tree (`scripts/check-push-receipt.sh`, fail-closed, tests in `make hooks-test`), else runs `pre-push-gate.sh --hook` (non-race tests of the changed packages only, mapped by `scripts/hook-test-pkgs.sh`, which fails closed to `./...` on go.mod/go.sum, any non-`.go` change under `internal/`/`web/`/`cmd/`, or a package left with no `.go` file; govulncheck only when go.mod/go.sum changed, since pre-commit misses merges, rebases and `--no-verify` commits and no CI job runs it; actionlint only when a workflow changed; no coverage floor/codecov dry-run/shard verify). The race suite, coverage floor, and shard split are left to the required CI checks (Test, Coverage Floor, Lint; `scripts/ci-shards.sh` is in the `code` paths filter so a shard-map change runs Lint). The per-check table lives in `docs/DEVELOPER.md`. The only override is `PUSH_GATE=full git push` (full gate, ignore the receipt); there is no skip value and any other value exits 2. Never `--no-verify`. Verify the wiring with `make doctor` (or `scripts/check-hooks.sh`).
- Make targets (`make help` lists all): `gate` (full local gate), `hooks-test` (hermetic tests for the pre-push hook, receipt check and package mapping), `doctor` (verify hook wiring + tool-version pins), `scan` (build the Docker image and grype it for HIGH+ CVEs), `test-shuffle` (`go test -race -shuffle=on`), `sync-tool-versions` (assert the golangci-lint pin agrees across CI and pre-commit, via `scripts/check-tool-versions.sh`), `vulncheck` (pinned `govulncheck@v1.1.4`), `coverage-floor` (one-way per-package coverage ratchet over `internal/` via `--bump`/`--lower`, jq-free; `scripts/coverage-floor.sh` + `scripts/coverage-floor.json`; policy in `docs/DEVELOPER.md`).
- Linter config: `.golangci.yml`. Always include a `// reason:` comment after any `//nolint:linter` directive -- this is now **enforced** by `nolintlint` (`require-explanation: true`), not just a convention, so a directive without the token fails the pre-commit hook, `make gate`, and CI alike. Pre-existing packages are excluded by path while their backlog is backfilled; each backfill PR deletes its own exclusion line, and the block disappears when the last one lands. Do not add a path there to silence a new finding. Keep the golangci-lint pin aligned across `ci.yml` and `.pre-commit-config.yaml` (`make sync-tool-versions` enforces it).
- golangci-lint version policy: the version pinned in CI (`ci.yml`) is the source of truth. `make sync-tool-versions` only aligns the config-file pins; it does not pin the binary you have installed locally, so `make gate` / the pre-commit hook can pass locally on a different golangci-lint version while CI flags issues your version does not (and vice versa). The `gosec` taint analyzers (e.g. `G704` SSRF on `httpClient.Do`) are especially prone to version-specific phantom findings that do not reproduce locally. When CI flags one of these, treat CI as authoritative: apply a per-site `//nolint:gosec // reason` (the reason is required) rather than chasing local reproduction. Bumping the CI pin needs a probe PR -- run against a clean cache and confirm no analyzer-regression findings before merging. (Pattern from sydlexius/stillwater `lint-config.instructions.md`.)
- CI workflows live in `.github/workflows/` (`ci.yml` -- incl. an image CVE `scan` job, `release.yml`, `nightly.yml`, `codeql.yml`). (Action SHA-pinning + `persist-credentials: false` are user-global CI/CD rules.)
- Releases: `git tag vX.Y.Z && git push --tags` triggers GoReleaser.

## Style (non-discoverable rules)

- Conventional commits: `feat:`, `fix:`, `docs:`, `ci:`, `chore:`, etc.
- `slog` for structured logs; `fmt.Printf` only for direct user-facing CLI output (timer, counts).
- Wrap errors with `fmt.Errorf("context: %w", err)`.

Everything else (formatting, naming, file layout) is enforced by `gofmt` + `.golangci.yml` -- follow the linter, not a written rule.

## Database (when adding stateful features)

- Pure-Go SQLite via `modernc.org/sqlite`. **Never reintroduce CGO** -- it breaks cross-compilation.
- WAL mode; goose-managed migrations in `internal/db/migrations/`.
- Repository pattern over interfaces (see `internal/cache/`) so storage stays swappable.
- Integration tests use real SQLite (in-memory `file::memory:?cache=shared` or temp file), not mocks.

### Reading PR comments (gh API gotcha)

If you fall back to raw `gh` instead of `/handle-review`: the `!` character triggers bash history expansion even inside double quotes, which breaks `--jq` filters using `!=`. Always use `select(.field == "value" | not)` instead:

```bash
gh api "repos/{owner}/{repo}/pulls/{number}/comments" --paginate \
  --jq '[.[] | select(.user.login == "some-bot" | not) | {id, user: .user.login, body}]'
```
